## Задача

Загрузить в прод новый датасет текстов. Требования заказчика:

1. **Все предыдущие данные должны выпасть из статистики** — дашборд, отчёты спикеров и
   модераторов, профили пользователей считают только активный датасет.
2. **Новый датасет должен явно отличаться от предыдущих** — по `file_id`, имени файла и
   группе экспорта.

Принятые решения (2026-08-12):

| Вопрос | Решение |
|---|---|
| Как привязать статистику | **Только активный датасет** — всё считается от `config('dataset.main_file_id')`. Параметра выбора датасета в отчётах не будет. |
| 39 087 неозвученных текстов `file_id = 8` | **Отбрасываются.** После переключения в очередь спикеров не попадают. |
| Итоговые счётчики спикеров (профиль, рейтинг) | **Обнуляются** — тоже считаются по активному датасету. |
| 368 неотмодерированных аудио `file_id = 8` | **Отбрасываются.** После переключения исчезнут из очереди модерации и останутся записанными, но непроверенными — а значит, невыгружаемыми навсегда. Принято сознательно. |
| Невыгруженный хвост file 8 (29 677 принятых аудио) | **Без срока.** Выгружается явным `--file-id=8` когда угодно, в том числе после переключения (#35). |

Старые данные остаются в базе, просто перестают отображаться.

**Все решения из таблицы исполнены 2026-08-12 вечером.** Решение по 368 аудио

Имя файла в записи `File` остаётся от первой партии (`207.xlsx`) — дописывание не меняет
`path`, различать датасеты нужно по метке.

В `.env` прода добавлено `DATASET_MAIN_FILE_ID=10`, конфиг пересобран.

**Датасет получил `file_id = 10`, а не 9, как планировалось.** Id 9 израсходован в тот же
день временной записью `File`, созданной при проверке R2 и сразу удалённой: MySQL не
переиспользует счётчик `AUTO_INCREMENT` после удаления строки. Функционально разницы нет,
но во всех командах и переменных нужен именно **10**. Проверять счётчик через
`information_schema.TABLES.AUTO_INCREMENT` бесполезно — значение там приблизительное,
перед вставкой оно показывало 9.

⚠️ Правка `.env` на проде: у файла **не было завершающего перевода строки**, поэтому
`echo 'X=1' >> .env` приклеил новую переменную к последней строке и сломал `AUDIO_DISK`.
Приложение работало на закэшированном конфиге и пользователи этого не заметили, но
`config:cache` в таком состоянии уронил бы загрузку аудио. Дописывать только через
`printf '\nX=1\n' >> .env`, потом обязательно `grep -c '^X=' .env`.

1. ~~**`SpeakTextController`** — запрос удерживаемого текста без фильтра по файлу.~~
   Закрыто в #38. 223 удерживаемых текста всё равно нужно освободить в Фазе 3:

3. **Кэш дашборда** — `DailyQuotaController`, `Cache::flexible` на 1 ч свежести / 2 ч
   устаревания. Ключ `daily_quota_data` чистит `optimize:clear`, а не `config:cache`:
   при переключении 2026-08-12 сначала выполнили только `config:cache`, и дашборд ещё
   какое-то время показывал бы счётчики старого датасета. Исправлено отдельным прогоном
   `optimize:clear && optimize`. **После смены `DATASET_MAIN_FILE_ID` всегда нужен
   `optimize:clear`, одного `config:cache` мало.**
4. ~~**`import:text-file`** пишет строки по одной внутри одной транзакции.~~
   Закрыто в #40: оба импорта (`import:text-file`, `import:excel-file`) пишут чанками,
   `--chunk=1000` по умолчанию.
5. **Дубликаты** — если в новом датасете встречаются предложения из старого, спикеры
   будут переозвучивать уже записанное. Для `.txt` — `import:check-duplicates`,
   для `.xlsx` отсев встроен в `import:excel-file` (внутри партии и против того, что
   уже лежит в этом же датасете). Против **других** датасетов ни то ни другое не
   проверяет — при добавлении партий это осознанный компромисс.
6. После переключения `edit_finished_texts_count` сразу станет равен размеру датасета:
   импорт проставляет `edit_finished_at` при загрузке. Это ожидаемо.
