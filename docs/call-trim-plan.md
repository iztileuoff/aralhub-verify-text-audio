# План: обрезка и расшифровка телефонных звонков

> Создано: 2026-10-24. **Бэкенд на проде с 2026-10-24** (`66b6099`); ждём фронт и сами звонки.
> ТЗ для фронта — `docs/frontend/call-trim.md`.

## Задача

Заказчик передал ≈ 8 ГБ телефонных разговоров без текста, каждый **не длиннее 2 минут**. Пять аккаунтов новой роли
**обрезчик** отрезают начало до разговора и тишину в конце, пишут весь разговор одним текстом
на каракалпакской латинице. Модератор принимает или возвращает работу. Нужна статистика по
каждому обрезчику. Принятое выгружается в `.tsv` в формате текущего экспорта.

## Принятые решения

| Решение | Почему |
|---------|--------|
| **Один звонок = одна обрезка, один текст** (вариант «а») | Меньше работы сейчас. Для STT (лимит 30 с) звонки потом придётся резать заново — для этого храним `trim_start_ms`/`trim_end_ms`. |
| **С модерацией** | Возврат с причиной тому же обрезчику; число возвратов — метрика качества. |
| **Отдельные таблицы**, не `texts`/`audio` | Всё в `texts`/`audio` привязано к активному датасету (`scopeMainFile`), счётчикам и экспортному гейту `exported_at`. Звонки в них сломали бы статистику и экспорт основного датасета. |
| **Режет фронт**, сервер только проверяет | Как в `long-audio-split`. Формат WAV проверяется по заголовку в PHP — ffmpeg на проде не нужен. |
| **Приватный бакет + временные ссылки** | Это разговоры реальных людей с номерами телефонов. Основной R2-бакет `aralhub-audio` публичный (`audio.iztileuoff.uz`) — туда звонки класть нельзя, даже в отдельную папку: в R2 доступ задаётся на весь бакет. |
| **8 ГБ грузятся в R2 напрямую** (`rclone` с ПК), а не через сервер | Диск сервера не нужен; потом artisan-команда регистрирует файлы в БД. |
| **Нормализацию громкости не делаем** | Сохраняем сигнал как есть; обработка — на этапе обучения. |
| **Числа — цифрами или словами**, `í` → `ı` автоматически | Сначала цифры запрещались; 2026-10-24 заказчик разрешил оба варианта. Строчная пара к `Í` в каракалпакской латинице — `ı`. |
| **Модерируют только админы** (super admin, admin) | Подтверждено 2026-10-24; модераторы (`role = 5`) звонков не видят. |

## Что выяснено о текущем коде

- ⚠️ **Права по ролям на бэкенде не проверяются.** `LoginController` выдаёт токену abilities по
  роли, но ни один роут их не требует — только `auth:sanctum`. Любой залогиненный, включая
  спикера, может вызвать любой admin-эндпоинт. Для «обрезчик видит только своё» это надо
  закрыть хотя бы для новой роли (Фаза 1).
- ⚠️ `DerivesTranscripts` делает `mb_strtolower`, а `mb_strtolower('Í')` = `í`, не `ı`. Для
  латиницы нужна своя нормализация (Фаза 3).
- `ProcessAudioJob` (ffmpeg) нигде не диспатчится; есть ли ffmpeg на проде — неизвестно.
- `exports` — общая таблица групп выгрузки; `Export::audios()` к звонкам отношения не имеет.

## Объём данных

WAV 16 kHz mono 16-bit = 32 КБ/с ≈ **115 МБ на час звука**. Результат больше исходников:

| 8 ГБ исходников | ≈ часов | ≈ результат |
|-----------------|---------|-------------|
| MP3 128 kbps | 140 | 16 ГБ |
| MP3/M4A 64 kbps | 280 | 32 ГБ |
| WAV 8 kHz 16-bit | 140 | 16 ГБ |

R2: ≈ $0.015/ГБ·мес, исходящий трафик бесплатный — 8 + 32 ГБ ≈ $0.6/мес.

Звонки ≤ 2 мин, при средней длине ≈ 1.5 мин это **≈ 5.5–11 тыс. звонков**. Один результат —
не больше ≈ 3.8 МБ.

### Фазы 1–6 — бэкенд ✅ (2026-10-24, ветка `feat/call-trim`)

Сделано по плану; отличия от первоначальной схемы отмечены.

- **Роль и доступ.** `RoleEnum::TRIMMER = 6` (`Trimmer`, permission `trimmer`), есть в
  `GET roles` и в создании/правке пользователей. Middleware `role:` и `role.deny:`
  (`EnsureUserHasRole` / `EnsureUserLacksRole`) смотрят на роль в строке пользователя, не на
  abilities токена. Обрезчик проходит только в `admin/calls/*` (свою часть) и `GET/PATCH profile`;
  все остальные группы `admin/*` и `admin/verify/*` отвечают ему `403`. Остальным ролям доступ
  к старым роутам не менялся — общая дыра «любой токен в любой эндпоинт» для них осталась.
- **Данные.** `call_recordings` + `call_recording_events`. В событии два пользователя:
  `user_id` — кто нажал, `trimmer_id` — чья работа (приём/возврат модератором засчитывается
  обрезчику). Диск `calls` (R2, приватный бакет), конфиг — `config/calls.php`.
- **Очередь.** Бронирование — условный `UPDATE … WHERE` по свободному звонку с повтором, а не
  `lockForUpdate` на чтении: пятеро одновременно получают разные звонки на любой СУБД. Звонок,
  возвращённый модератором, не уходит другому даже после истечения брони.
- **Сдача.** WAV проверяется по заголовку (`Pcm16kMonoWavRule`), длительность считает сервер.
  Текст — `KarakalpakLatinRule`: кириллица и чужие символы → `422` (цифры разрешены с 2026-10-24); перед проверкой
  `í → ı`, типографские кавычки → обычные, переносы строк → пробелы. Нормализация —
  `DerivesLatinTranscripts` (`Í → ı`).
- **Модерация, статистика** — как в ТЗ. День/период считаются в часовом поясе приложения
  (UTC), как и остальные отчёты проекта.
- **Команды.** `calls:register` (регистрация залитого в бакет, идемпотентна, предупреждает о
  форматах, которые браузер не откроет) и `calls:export` (`.tsv` + список файлов). См. `README.md`.
- **Тесты.** 89 новых (`tests/Feature/Api/V1/Calls`, `tests/Feature/CallCommandsTest.php`).
  Набор целиком перестал помещаться в 128 МБ PHP (он и до этого был на пределе — пик 128 МБ),
  в `phpunit.xml` поднят `memory_limit` до 512M.
